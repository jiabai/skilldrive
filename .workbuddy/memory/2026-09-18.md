## 启动 desktop-client 做人工核验（环境坑，重要）

bicho 要求启动看 Agent 视角效果。踩到两个环境坑，已解决，记下来避免重复排查：

1. **`ELECTRON_RUN_AS_NODE=1` 会污染子进程**。WorkBuddy 自身是 Electron 应用，会向子进程注入该变量，导致 `electron.exe` 以纯 Node 模式运行，主进程第一行 `import { app } from "electron"` 就炸：`TypeError: Cannot read properties of undefined (reading 'exports')`（栈里有 `cjsPreparseModuleExports`）。日志末尾写 `Node.js v20.18.3` 而不是 Electron 版本，就是这个信号。启动时必须 `env -u ELECTRON_RUN_AS_NODE`。
2. **GPU 进程在沙箱里起不来**，报 `FATAL:gpu_data_manager_impl_private.cc(423) GPU process isn't usable. Goodbye.`。加 `--no-sandbox --disable-gpu --in-process-gpu --disable-gpu-sandbox --disable-features=VizDisplayCompositor` 后正常。

可用启动式（dev 模式，改 renderer 免重新打包）：

```
npx vite --port 5199 --strictPort        # 后台
env -u ELECTRON_RUN_AS_NODE VITE_DEV_SERVER_URL=http://localhost:5199 \
  ./node_modules/electron/dist/electron.exe . --no-sandbox --disable-gpu --in-process-gpu --disable-gpu-sandbox --disable-features=VizDisplayCompositor
```

改了 `electron/` 下的主进程代码才需要 `npx vite build --config vite.electron.config.ts`（preload 同理换 `vite.preload.config.ts`）。

截屏验证走不通：PowerShell 工具禁止 `Add-Type`（无法用 .NET 截屏），Bash 里调 powershell.exe 被安全策略拦。改用 vitest 渲染测试验证 UI 更可靠，已新增 `src/__tests__/agent-skills-view.test.tsx`（8 个用例：只列已安装、按有效数排序、共享目录标注、下钻只看该 agent、返回与查看回调、missing / empty 两态）。

两个关键实现事实（这次为改计划实测出来的，实现时直接用）：

- **项目没有任何下拉菜单 / popover / 点击外部关闭的现成实现。** `ui-primitives.tsx` 只导出 `Button`、`Card`、`CardHeader`、`CardContent`、`CardTitle`、`CardDescription`、`Badge`、`PageIntro`、`Input`、`Dialog`、`Drawer`；`Escape` 处理只在 `Dialog` 与 `Drawer` 内部。依赖里只有 `lucide-react` 做图标，没有 Radix 之类的组件库。**因此「更多」菜单采用行内展开（点开后该行往下长出一条），不做浮层**，避开浮层定位、外部点击关闭、Esc 处理与带滚动容器的裁切风险。
- **`Button` 的 variant 取值为 `primary | secondary | outline | ghost | destructive | nav-active`**，`btn--destructive` 类已存在。但 `local-skills-view.tsx:301` 的删除按钮用的是 `secondary`，本入口改用 `destructive` 是有意的不一致（本入口确认护栏更弱，用视觉警示补偿），已作为验收项写进计划。

## 严重事故：git stash 触发后台 gc 被中断，.git/refs 被移入回收站（2026-09-18 18:51）

- 为做上述对照实验执行了 `git stash push -- <6 个文件>`，整条命令随后被 SIGTERM 中断。
- 之后 git 报 `fatal: not a git repository`。诊断发现 **`.git/refs` 整个目录消失**，`.git` 其余部分（HEAD、objects、index、logs、packed-refs）都在。
- **根因**：`git stash` 完成后触发后台自动 gc，gc 的 `pack-refs` 先删散落的 ref 文件、`repack` 再删旧 pack。两步执行到一半进程被杀，refs 树与 `objects/pack/*.pack` 已被移走，而 `packed-refs` 尚未更新，仓库立刻失效。**这些「删除」实际是移进了回收站，不是硬删除。**
- **恢复**：按 `recover-deleted-git-from-recycle-bin` 技能，解析 `D:\$RECYCLE.BIN\<SID>\$I*` 元数据取原始绝对路径，回写 729 个条目（193 目录 + 536 文件），再清理崩溃残留的 `index.lock`（0 字节）与 `index.stash.5508`。`git fsck --full` 零缺失对象，`refs/heads/main` 恢复为 `1e533ef...`，与 reflog 一致。
- **教训：本仓库不要再使用 `git stash`。** 需要工作区对照实验就走「备份文件 + `git checkout HEAD -- <paths>` + 从备份还原」这条路线。
- 诊断途中另踩两坑：`$I` 的 FILETIME 必须用 `struct.unpack("<Q", blob[16:24])` 读，写成 `<QQ` 会 OverflowError；shell 里 `cd /d/... && git ...` 组合不稳定，报 not a git repository 往往是 cwd 没生效，调 git 优先用 Python 的 `subprocess(cwd=...)`。

## 不用 git stash 做基线对照的可行方法（2026-09-18 实测成功）

事故之后需要一种不碰工作区的对照实验手段，实测如下：

1. `git worktree add ../skilldrive-baseline --detach HEAD` 建干净基线工作树。
2. 复用依赖**不要**用 `cmd //c mklink /J`：Git Bash 里 `/J` 会被路径转换破坏，cmd 会掉进交互模式什么都不做。改用 PowerShell 的 `New-Item -ItemType Junction -Path <baseline>/desktop-client/node_modules -Target <real>/desktop-client/node_modules`。
3. 跑完测试后，**先删联接再删工作树**：`[System.IO.Directory]::Delete($link, $false)`（PowerShell 工具禁止调 cmd.exe），再 `git worktree remove --force`、`git worktree prune`。**绝不能在联接还在时执行 `git worktree remove -f`**，那会穿透联接删掉真实的 `node_modules`。
4. 实测一次 `app.test.tsx` 基线对照约 40 秒完成，得到与工作区完全相同的 `4 failed / 49 passed` 和相同用例名，全程不改动工作区任何文件。
