# Agent 视角：按 Agent 浏览本机 SKILL

> 状态：已确认（2026-09-18，bicho 采纳全部七项建议）。规格已定稿，配套执行计划见 `../exec-plans/2026-09-18-agent-skill-viewer.md`。
> 本文档定义需求与已确认决策，实现细节见执行计划。

## 一、需求复述（我理解你说的）

1. 桌面客户端左侧边栏新增一个一级导航项，暂称「Agent 视角」。
2. 点击后进入 Agent 列表页，只列出本机已经安装的 agent，例如 Codex、Claude Code、WorkBuddy。
3. 点击其中某一个 agent，进入该 agent 的详情页。
4. 详情页展示该 agent 的 SKILL 目录下的全部 SKILL。

一句话概括：把现在平铺的「本机 SKILL 清单」，增加一个「先选 agent，再看它目录里的 SKILL」的两级下钻入口。

## 二、与现有功能的关系

桌面客户端已经有两块与它重叠的功能：

| 现有功能 | 位置 | 视角 | 覆盖内容 |
|---|---|---|---|
| Agents 面板 | 设置抽屉内 | Agent 优先 | 只展示安装状态、检测目录、分发目标，不列 SKILL |
| 本地 SKILL 视图 | 一级导航，位于首页与更新之间 | SKILL 优先 | 跨 agent 平铺聚合，来源 agent 只作为一列 |

因此新模块不是从零建设：

- 「已安装 agent 列表」的数据源已存在，来自 agent detection snapshot。
- 「某个目录下的 SKILL 列表」的数据源也已存在，来自 local skill inventory，每行已带 `sourceAgents` 与 `packageRootPath`。
- 缺失的部分是：agent 优先的两级导航结构，以及围绕单个 agent 组织信息的展示层。

结论：v1 预计不需要新增后端接口，也不需要新增 IPC 通道，主要是 renderer 侧的信息架构重组与少量派生逻辑。这一点需要在本草稿确认后由设计文档二次核实。

## 三、完善后的需求

### 3.1 信息架构

侧边栏自上而下：首页、更新、本地 SKILL、项目，以及新增的「Agent 视角」。

Agent 视角内部为两级：

- 第一级：Agent 列表，只含已安装 agent。
- 第二级：Agent 详情，展示该 agent 的 SKILL 目录内容。

### 3.2 第一级：Agent 列表

- 只显示被判定为已安装的 agent，未安装的不出现在这里（它们仍可在设置抽屉的 Agents 面板中查看，那里是配置与诊断入口）。
- 每项展示：agent 显示名、图标（或首字母标记）、该 agent 下有效 SKILL 数量、SKILL 目录路径（截断显示，可完整查看）。
- 排序规则：按有效 SKILL 数量降序，数量相同时按显示名排序。
- 顶部提供「重新检测」入口，复用现有 rediscovery 能力。
- 点击整行进入第二级。

### 3.3 第二级：Agent 详情

- 顶部区域：返回上一层、agent 显示名、SKILL 目录绝对路径、【打开目录】与【复制路径】。
- 列表字段：SKILL 名称、版本、描述、目录名、校验状态。
- 分类布局的 agent（Hermes Agent）保留 category 层级展示。
- 共享路径提示：当该 agent 的 SKILL 目录与其它 agent 共享同一物理目录时，明确提示共享关系。
- 空状态需区分三种：目录不存在、目录存在但为空、目录内子项存在但没有有效 `SKILL.md`。

### 3.4 判定与数据规则

- 已安装判定：沿用现有检测快照的启发式判断，即检测目录在文件系统中存在，不代表可执行程序或版本已检测。
- SKILL 数量口径：按包含根路径 `SKILL.md` 的有效包根计数，与本地 SKILL 视图保持一致。
- 数据新鲜度：进入视图时使用当前已加载的快照，用户可手动刷新，不引入后台轮询。
- 共享物理目录只扫描一次，结果按覆盖关系挂到多个 agent 下。

### 3.5 状态与反馈

- 快照尚未加载：展示加载中占位。
- 检测失败或快照为空：展示可操作的空状态，并提供重新检测。
- 单个 agent 目录不可读：该 agent 项标注错误原因，其余 agent 不受影响。

### 3.6 国际化

新增文案需同时补齐中文与英文，包括导航项名称、两个层级的标题与说明、空状态、错误状态，以及统计文案。

### 3.7 安全与边界

- 文件系统读取、目录枚举都留在 Electron 主进程，renderer 只消费 IPC 返回的序列化状态。
- renderer 不接收原始文件内容，只接收结构化元数据。
- 本模块不改动任何 agent 目录，只读。
- 本模块不引入新的持久化，快照仍为运行时状态。

## 四、非目标（v1 不做）

- 不做 agent 的安装、卸载、升级。
- 不做 agent 可执行程序与版本的检测。
- 不在该视图内编辑 SKILL 文件内容。
- 不改变现有分发流程与审批语义。
- 不改变设置抽屉中 Agents 面板的信息内容。
- 不引入后台轮询或自动刷新。
- 不改变后端契约。

## 五、已确认的决策

七个问题已于 2026-09-18 由 bicho 确认，全部采纳标注为「建议」的方案。结论摘录：

1. 与「本地 SKILL」视图的关系：新增一级导航，两个视图并存。
2. 「该 agent 的 SKILL 目录」定义：只显示该 agent 的默认分发目标（owned target），共享路径按覆盖关系标注。附带确认，Codex 与 Cline、Warp 共享 `~/.agents/skills`，因此三者看到的内容相同，属于预期结果。
3. 已安装但无有效 SKILL 目录的 agent：显示，并标注具体状态。
4. 详情页里单个 SKILL 的操作：v1 只读浏览，加【打开所在目录】，不含上传，不含删除。
5. 导航项名称与图标：「Agent 视角」，图标 Bot。
6. 未安装 agent 入口：不显示。
7. SKILL 数量口径：按含根 `SKILL.md` 的有效包根计数。

原始问题、候选方案与理由保留如下，供追溯。

### 问题 1：与「本地 SKILL」视图的关系

- A. 新增一级导航，两个视图并存（建议）。理由：本地 SKILL 视图承担上传操作，其对齐键是 SKILL 名称与服务端存在状态；Agent 视角承担浏览与巡检，两者操作语义不同，合并会让上传入口的语义变模糊。
- B. 把「本地 SKILL」改造成两级结构，不新增导航项。
- C. 新增导航项，同时把「本地 SKILL」降级为 Agent 视角内的一个「全部」聚合视图。

### 问题 2：如何定义「该 agent 的 SKILL 目录」

- A. 只显示该 agent 的 owned target，即默认分发目标，共享路径按覆盖关系标注（建议）。理由：与现有分发语义一致，一个物理目录只归属一个主 agent，避免同一个 SKILL 在多个 agent 下重复出现。
- B. 显示 owned target 加 compatibleReadPaths，即该 agent 能读到的全部路径。

需要确认一个既有架构事实：Codex 的 owned target 是共享的 `~/.agents/skills`，因此点进 Codex 看到的内容与 Cline、Warp 相同，都是那 69 项。若采用 A，这是预期结果。

### 问题 3：已安装但没有有效 SKILL 目录的 agent 是否显示

- A. 显示，并标注具体状态，例如「未找到 SKILL 目录」或「目录为空」（建议）。理由：本机 `~/.codex` 属于这种情况，隐藏会让用户以为检测漏了。
- B. 隐藏，列表只保留有内容的 agent。

### 问题 4：详情页里单个 SKILL 支持哪些操作

- A. 只读浏览，加上【打开所在目录】（建议 v1）。理由：先把浏览跑通，操作类需求后叠。
- B. 在 A 基础上增加【上传到服务端】，复用现有上传链路。
- C. 在 A 基础上增加【删除本地 SKILL】。建议 v1 不做，属于破坏性操作，需要独立设计确认流程。

### 问题 5：导航项名称与图标

- 名称候选：Agent 视角、按 Agent 浏览、Agents。建议「Agent 视角」。
- 图标候选：Bot、Blocks、LayoutGrid。建议 Bot。

### 问题 6：是否在列表里保留未安装 agent 的入口

- A. 不显示（建议，与你原话一致）。
- B. 显示为灰置项，点击后提示如何安装。

### 问题 7：SKILL 数量口径

- A. 按有效包根计数，即含根 `SKILL.md` 的目录（建议），与本地 SKILL 视图口径一致。
- B. 按目录项计数，包含无效目录。

## 六、验收标准（初稿）

1. 侧边栏出现新增导航项，点击后进入 Agent 列表。
2. Agent 列表只包含被判定为已安装的 agent。
3. 列表项展示 SKILL 数量与目录路径，数量与详情页实际条数一致。
4. 点击任一 agent 进入详情页，展示该 agent SKILL 目录下的全部有效 SKILL。
5. 共享物理目录按覆盖关系正确归属，不重复扫描。
6. 有效 SKILL 数量为 0 的 agent，展示明确空状态，不显示为加载失败。
7. 分类布局 agent 保留 category 层级。
8. 扫描过程只读，不修改任何 agent 目录。
9. 未安装 agent 不出现在该视图。
10. 中英文文案齐全，切换语言后无缺失或回退。
11. 现有本地 SKILL 视图、更新流程、分发流程行为不退化。
